# 从 0.1 迁移到 0.2

> 状态：已接受\
> 适用版本：从 EAVP 0.1.x 升级到 0.2.0\
> 规范性范围：实验性公共 C++ API 的源代码迁移；不定义二进制兼容承诺

0.2.0 在 1.0 前的实验性 API 上进行了有意的破坏性调整。迁移后，所有失败继续以 `eavp::Status` 或 `eavp::Result<T>` 表达，异常不得跨公共模块边界。以下代码均为最小调用方示例。

## Buffer：从裸指针访问迁移到 plane 映射

0.1 的单一数据视图不能表示多 plane 或映射生命周期。旧代码：

```cpp
eavp::Buffer buffer = make_buffer();
std::uint8_t* bytes = buffer.mutable_data();
bytes[0] = 0x42;
consume(buffer.data(), buffer.size());
```

0.2 使用 `map_plane()`，并让 `MappedRegion` 的作用域覆盖访问期：

```cpp
eavp::Result<eavp::MappedRegion> mapped =
    buffer.map_plane(0U, eavp::MapMode::kReadWrite);
if (!mapped.ok()) {
    return mapped.status();
}
mapped.value().mutable_data()[0] = 0x42;
consume(mapped.value().data(), mapped.value().size());
```

## VideoFrame：从单 stride 迁移到 VideoFormat 与 PlaneLayout

0.1 调用方以帧尺寸、像素格式和单一 stride 描述图像。0.2 将这些约束集中到 `VideoFormat`，每个 plane 都有 offset、size 和 stride：

```cpp
const std::vector<eavp::PlaneLayout> planes{
    eavp::PlaneLayout(0U, 1920U * 1080U * 3U, 1920U * 3U)};
eavp::Result<eavp::VideoFormat> format = eavp::VideoFormat::create(
    eavp::PixelFormat::kRgb24, 1920, 1080, eavp::MemoryDomain::kCpu,
    planes);
if (!format.ok()) {
    return format.status();
}
eavp::Result<eavp::VideoFrame> frame = eavp::VideoFrame::create(
    buffer, format.value(), pts, time_base);
if (!frame.ok()) {
    return frame.status();
}
```

`Buffer` 的 plane 数和每个 `PlaneLayout` 必须与 `VideoFormat` 完全一致；NV12 和 YUV420P 等格式应显式传入全部 plane。

## MediaPacket：从构造函数迁移到带流格式的工厂

0.1 的 Packet 构造不要求调用方说明字节的封装形式。0.2 通过 factory 同时校验 Codec、`EncodedStreamFormat` 和 codec 配置：

```cpp
eavp::CodecConfigData codec_config;
eavp::Result<eavp::MediaPacket> packet = eavp::MediaPacket::create(
    payload, eavp::CodecId::kH264, eavp::EncodedStreamFormat::kAnnexB,
    0, pts, dts, duration, time_base, key_frame, codec_config);
if (!packet.ok()) {
    return packet.status();
}
```

测试 Reference Backend 的输出必须使用 `CodecId::kReference` 与 `EncodedStreamFormat::kReference`；这些字节不是 H.264 或 H.265 码流。

## Result：从可复制取值迁移到 move-only 所有权转移

`Result<T>` 不再可复制。对于 `std::unique_ptr` 等专有值，检查成功后使用 `take_value()`：

```cpp
eavp::Result<std::unique_ptr<eavp::VideoEncoder> > created =
    provider->create_video_encoder();
if (!created.ok()) {
    return created.status();
}
std::unique_ptr<eavp::VideoEncoder> encoder = created.take_value();
```

只读检查可继续使用 `value()`；不要通过复制 `Result<T>` 延长其内部值的所有权。

## Provider：注册、冻结并选择

平台在构建 Pipeline 前完成注册并冻结 Registry。以下示例选择 Reference Processor，任一步失败都应由调用方处理：

```cpp
eavp::BackendRegistry registry;
std::shared_ptr<eavp::MediaBackendProvider> provider =
    eavp::create_reference_backend(eavp::ReferenceBackendOptions());
if (!provider) {
    return eavp::Status(eavp::StatusCode::kResourceExhausted);
}
eavp::Status registered = registry.register_provider(provider);
if (!registered.ok()) {
    return registered;
}
eavp::Status frozen = registry.freeze();
if (!frozen.ok()) {
    return frozen;
}

eavp::Result<eavp::VideoProcessorConfig> config =
    eavp::VideoProcessorConfig::create(format, format, 0, 0,
                                       format.width(), format.height(), 0);
if (!config.ok()) {
    return config.status();
}
const eavp::VideoProcessorRequest request(
    config.take_value(), std::vector<eavp::VideoProcessingOperation>(),
    1U, 1U, true, eavp::SelectionConstraints("reference"),
    eavp::SelectionPreferences(std::vector<std::string>(), false, false));
eavp::Result<eavp::ProcessorSelection> selected =
    registry.select_video_processor(request);
if (!selected.ok()) {
    return selected.status();
}
eavp::Result<std::unique_ptr<eavp::VideoProcessor> > created =
    selected.value().provider->create_video_processor();
if (!created.ok()) {
    return created.status();
}
std::unique_ptr<eavp::VideoProcessor> processor = created.take_value();
```

冻结后 `register_provider()` 返回失败。运行期不支持动态注册或热插拔；真实硬件、容器和协议能力仍需各自的独立规格。
