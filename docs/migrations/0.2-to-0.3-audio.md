# 从 0.2 迁移到 0.3b 音频 API

> 状态：已接受\
> 适用版本：从 EAVP `0.2.0` 升级到 `0.3b` 开发能力\
> 规范性范围：实验性公共 C++ `AudioFrame` API 的源代码迁移；不定义二进制兼容承诺

`AudioFrame` 在 1.0 前仍是实验性接口。0.3b 将松散的采样参数收敛为 `AudioFormat`，使字节大小、字节序、声道布局和内存域可被精确验证。所有 factory 失败继续通过 `eavp::Status` 或 `eavp::Result<T>` 返回，异常不得跨公共模块边界。

## 迁移调用

0.2 将格式和样本数直接传入 `AudioFrame::create()`：

```cpp
// 0.2
AudioFrame::create(buffer, SampleFormat::kSigned16,
                   48000, 2, 480, pts, time_base);
```

0.3b 先建立不可变的 `AudioFormat`，再传入每声道样本数与时间线中断标记：

```cpp
// 0.3b
AudioFormat format = AudioFormat::create(
    SampleFormat::kSigned16LittleEndian, 48000,
    AudioChannelLayout::kStereo,
    AudioSampleLayout::kInterleaved,
    MemoryDomain::kCpu).take_value();
AudioFrame::create(buffer, format, 480, pts, time_base,
                   discontinuity);
```

生产调用方应检查两个 factory 的 `Result`，上例仅用于突出签名变化。`Buffer` 必须是 CPU 域的单一 plane，且其字节数严格等于 `samples_per_channel * format.bytes_per_pcm_frame()`。

## 语义变化

- `samples` 更名为 `samples_per_channel`：`480` 表示每个声道各有 480 个采样点，而不是 stereo 总计 960 个值。
- `SampleFormat::kSigned24In32LittleEndian` 对应 ALSA `S24_LE`：它使用 **32-bit little-endian container**，其中 24 位有效；它不是 3-byte packed `S24_3LE`。
- `pts` 表示本 `AudioFrame` 的**首个 PCM 采样点**，而不是读操作结束时刻。0.3b 使用 `TimeBase(1, 1000000)` 的 `CLOCK_MONOTONIC` 时间线；48 kHz、480 samples/channel 的连续帧相差 10000 us。
- 原始 PCM `AudioFrame` 没有 DTS。只有后续编码生成的 `MediaPacket` 才分别保存 PTS 与 DTS。
- `discontinuity=false` 表示正常启动或连续采集；XRUN/suspend 恢复会丢弃未完成数据、重新锚定，且恢复后的第一个完整帧为 `true`。它不是静音、丢包补零或设备自动重连标记。

调用方不得保留旧的 `samples()` 或未表达 endian/container 的枚举值作为兼容分支。需要兼容 0.2 与 0.3b 的代码应在各自版本适配层构造明确的 `AudioFormat`，不要在公共 API 中重新引入含糊字段。
